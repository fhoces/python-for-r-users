Where things live.

The first file, bundle paths, is small, and it is the one every other file imports. Its only job is to know where things are. The raw bundle. The SQLite database. The folder for exports. Two small private configuration files. Having one module that knows all the paths means that when a folder moves, you change one line, not twenty.

It starts from the file's own location. Path, of double underscore file, then resolve, then parent, then parent again. Read that as: the folder that contains the folder that contains this script. From there every other path is built with the slash operator. B S Z dir, slash data raw, slash bundle dot sqlite. The slash is not string concatenation. It is an operator that the path library overloads to join path pieces, with the right separator for the operating system. In R you would write here, here, or file dot path. The difference is that a Python path is an object with methods. It can tell you whether it exists, whether it is a folder, read its own text, or search below itself for files.

Next, an environment variable with a default. O S dot environ dot get, the name B S Z bundle dir, and an empty string as the fallback. If the variable is set, the bundle lives there. If not, the code uses a default path inside the repository. In R, this is Sys dot getenv with unset equals an empty string. The variable lets a co-author, or a second copy of the repository, point at the data somewhere else without editing any code.

Then, the error message. When the bundle is missing, the function raises a file not found error, and the message says three things: the path it tried, that the data are confidential and not in git, and the name of the environment variable that would fix it. That is the whole craft of a good error. Say what was expected, where you looked, and what to do. The alternative, letting the script fail three functions later with a bare key error, costs the next person half an hour. In R, the same message would go into stop.

One more idiom. A helper called find in bundle searches the whole bundle for a file by name, using r glob, a recursive glob. Then it insists on exactly one match. Zero matches is an error, and so is two. Two matches would mean the bundle contains two copies of a file, maybe an old one and a new one, and picking the first silently is how a reproduction ends up using last year's data. Insisting on exactly one turns that into a loud failure on day one.

The last helper reads a small CSV that may contain comment lines. It drops every line that starts with a hash, then passes the rest to the C S V module's dict reader, which yields one dictionary per row. That way a configuration file can carry its own documentation at the top. None of this is clever. It is the kind of code that makes everything after it boring, which is exactly what you want from paths.
