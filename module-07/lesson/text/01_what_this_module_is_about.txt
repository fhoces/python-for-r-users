What this module is about.

This is module seven of Python for R users. Module six was about reading a codebase you did not write. This one is about the Python that sits around a SQL file in a real reproduction. Not the SQL itself. The SQL course covers that. Here the SQL is a black box that turns one big table into four smaller ones, and the job of Python is everything before and after it.

The source is a public repository called opa prop forty. One folder in it, the B S Z analysis folder, reproduces part of a published paper about California billionaires. The authors shared their raw data under confidential terms: daily snapshots from Forbes, one row per person per day, about six million rows. The reproduction rebuilds the authors' intermediate tables from that raw data, and then checks them, cell by cell, against the authors' own spreadsheets.

Four Python files do the work, and you will meet them in order. The first, bundle paths, knows where every file lives. The second, load bundle, reads the raw files and puts them into a SQLite database. The third, run s q l, runs a shared SQL file against that database and writes the resulting tables to text files. The fourth, check r t b c a, compares those text files with the authors' answer keys and with the same files written by R. There is also an R twin, run s q l dot R, which runs the same SQL file from R. It is there so that two independent programs can be compared.

That last point is worth holding on to. The SQL file is the single source of truth. Python runs it. R runs it. Each language writes its own exports. If the two sets of exports agree, any bug left must be in the SQL or in the data, not in the plumbing around them. The plumbing is what this module is about, and plumbing is where most silent errors in a reproduction come from: a missing value that turned into an empty string, a float that got rounded on the way out, rows that came back in a different order.

Because the real data are confidential, the drills run on a synthetic panel in the same shape. Sixty invented people, about three hundred dates, fortunes that follow random walks. You build it once with python data slash build r t b sample dot p y. The drills then ask you to write four functions: a loader, a runner, a comparison, and a parity check. A grader imports your file and tells you, drill by drill, whether each function does what the real one does.

The framing is the same as the rest of this course. For each Python idiom, you will hear the R habit it maps to. Sometimes the mapping is direct, like path handling. Sometimes Python has a tool R lacks, like execute script. And sometimes R has to do by hand what Python does in one call, like splitting a SQL file into statements. Knowing which is which is half of reading a pipeline like this one.
